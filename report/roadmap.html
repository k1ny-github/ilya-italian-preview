Что делаем дальше — один конечный цикл

1. Решения владельца

  • Выбрать А / Б / В оформления приглашения к тесту. Сейчас на сайте А, другие — только сравнение.
  • Решить, переносим ли выбранный компактный планшетный hero в основной сайт. Проба выбрана, но пока отдельно.
  • Принять длинные описания 320–360 или согласовать отдельные сокращения. Шрифт не уменьшаем, текст не скрываем.
  • Пройти оставшиеся секции страницы и собрать только конкретные дефекты. Не запускать новый полный редизайн.

Выход: один список окончательных изменений с точным источником выбранного варианта.

2. Один пакет внедрения

  • Frontend переносит только выбранное.
  • Дизайнер сверяет видимый результат по шести диапазонам.
  • Архитектор проверяет источники, ограничения и фиксацию; не собирает интерфейс вместо исполнителей.
  • Делается контрольный commit, сохраняются предыдущая и новая версии.

Выход: одна версия, готовая к полной приёмке, без конкурирующих «финальных» файлов.

3. Материалы и условия

  • Восемь реальных ответов преподавателя для FAQ.
  • Условия первой встречи: длительность, порядок записи и продолжения занятий.
  • Окончательный календарь, доступные слоты и часовой пояс; проверка Telegram.
  • Проверенные сведения о квалификации, документы при необходимости, разрешения на портреты и отзывы.
  • Проверка публичного использования учебных материалов и элементов Miro.
  • Окончательные юридические документы и сведения оператора — отдельная задача с юристом.

Выход: содержание соответствует реальным услугам. Временные тексты не выдаются за утверждённые документы.

4. Общая проверка и коммерческий запуск

  • Шесть диапазонов: 320 / 360 / 480 / 640 / 960 / 1200. Внутри диапазонов страница сохраняет работоспособность, отдельные 800/959-композиции не вводятся.
  • Реальные телефон, планшет и ПК; отдельно браузеры iOS/Android, если это нужные устройства посетителей.
  • Путь: открыть сайт → понять предложение → при желании пройти тест → увидеть результат → выбрать время или написать.
  • Проверить отзыв/FAQ/клавиатуру/закрытие диалогов, отсутствие потери текста и обрезки важных элементов.
  • Выбрать окончательный домен/размещение. Текущая GitHub-ссылка — review, не автоматическое разрешение коммерческого запуска.
  • Аналитику добавлять только по отдельному решению, когда понятны цель и необходимые документы.

Выход: приёмка владельцем всей страницы и явное решение о запуске.

После запуска, отдельным этапом

  • Английская и итальянская версии.
  • Другие палитры/полная тёмная тема.
  • Мужской фотокандидат и осмысленные A/B-тесты при наличии трафика.
  • Переключение оболочек/тем через backend — только если появится практическая потребность.

Эти идеи не блокируют завершение нынешнего лендинга и не являются текущим заказом.

Правило остановки

Новый круг нужен, если есть конкретный дефект, незакрытое решение из списка выше или наблюдаемая проблема посетителя. Формулировка «может, ещё покрасивее» сама по себе не расширяет задачу. После выбранного пакета — один проход исправлений, одна подтверждающая проверка и фиксация результата.

Что ещё плохо

FAQ без утверждённых ответов; длинные тексты узких карточек; светлый контур коллажа; неутверждённые условия/документы/разрешения; нет подтверждённой полной проверки на физических устройствах. Успешная сборка не закрывает эти пункты.

Версия для просмотра владельцем. Юридические материалы и коммерческий запуск не утверждены.
